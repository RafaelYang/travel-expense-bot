## Project learnings

- The app is a Next.js 16 + Prisma/PostgreSQL shared travel-expense tracker with Google/LINE authentication, trip invitations, exchange-rate conversion, image attachments, and a LINE Messaging API bot.
- Email invitations use Gmail SMTP with the production `GMAIL_USER` and `GMAIL_APP_PASSWORD` variables. Both the trip share modal and settings page reuse `EmailInviteRoleSelector` to offer only `member` (can log expenses) and `viewer` (read-only); the route allowlists the role and never accepts `owner`. Sending creates or refreshes a seven-day UUID invite, including its selected role, inviter, and expiry. Acceptance revalidates that stored role, requires Google sign-in with the exact normalized invited email, and atomically creates the `TripMember`; the email and landing page display the granted access. On a recipient's first successful Google sign-in, Auth.js with `PrismaAdapter` automatically creates the `User` and linked `Account`, returns to the invite page, and redeems the invite without a separate registration form. Owners and members may send invitations; viewers may not.
- Verified checks from the project root: `npm test` passes 129 security/money/image/reconciliation/statistics/exchange-rate/PWA/date/timeline/active-trip/realtime-version/trip-country/settings/email-invite/UI/migration regression tests, `npx tsc --noEmit` passes, `npm run lint` succeeds with no errors (9 existing image performance warnings), and `npm run build` succeeds on Next.js 16.2.6. There is no `prisma/migrations` history yet.
- Treat expense and deposit authorization as a child-resource invariant: every read/update/delete must bind the child ID to its `tripId`, then verify the acting user is an eligible trip member. LINE postbacks must additionally bind the sending `lineUserId` to that same trip before mutating data.
- Reuse `src/lib/trip-access.ts` for expense/deposit mutations. Writable roles are `owner` and `member`; `viewer` is read-only. LINE expense mutations additionally require the sender to own the expense.
- Expense image delivery is intentionally sessionless for LINE servers but requires the expiring HMAC query parameters produced by `src/lib/expense-image-signing.ts`. The trip RSC and full-trip GET omit the Base64 `images` column, use the membership-guarded `src/lib/expense-image-metadata.ts` count query, and build 24-hour signed references from those counts; keep both loaders aligned. PATCH resolves valid references back to stored values. Production should set `IMAGE_URL_SIGNING_SECRET`; the current fallback order is `AUTH_SECRET`, then `LINE_CHANNEL_SECRET`. Keep the response private/no-store and never restore unsigned ID-only URLs.
- `LineBotState.activeTripId` currently stores either `tripId` or `tripId:currency`; consumers must split the value before using it as a Prisma trip ID. Prefer separate typed columns when the schema is next migrated.
- Monetary values currently use `Float`. `src/lib/money.ts` deliberately excludes missing foreign conversions and foreign-currency deposits from base-currency totals; never silently substitute a 1:1 rate. A future schema migration should use exact decimal/minor-unit values and persist deposit conversions consistently.
- Web expense and deposit amount controls must use `type="number"`, `inputMode="decimal"`, and `step="any"`; the HTML default step is 1 and will block decimal submission with a native `stepMismatch` before the positive-number API schemas run. Keep this contract aligned across create and edit fields; `tests/money-input.test.ts` guards the three current form locations.
- New-trip start/end controls must render as `type="date"` from the first paint. Do not swap an empty text input to `date` on focus: mobile Safari/WebViews may consume the initiating tap without opening the native picker. At 600 px and below, stack the two controls and retain 48 px touch targets; constrain the end date with the selected start date and vice versa.
- Expense reconciliation preserves the booking-time `convertedAmount` and `exchangeRate`, stores a foreign-card final charge separately in nullable `settledAmount`, and uses it in totals only while `reconciledAt` is set. Foreign-card confirmation requires a positive final charge; changing amount, currency, or payment method clears both reconciliation fields unless the same PATCH explicitly re-confirms with a valid new final charge. LINE money and currency edits must clear both fields too.
- Optional expense adjustments use three independent trip settings: `serviceFeeEnabled`, `shopbackRewardEnabled`, and `creditCardRewardEnabled`. The legacy `expenseAdjustmentsEnabled` column remains as their OR for old-client/application rollback compatibility. Card/extra-spend create, edit, and batch-reconciliation flows must expose and accept only the individually enabled non-negative finite base-currency fields. Canonical net spend is the estimated or reconciled base amount plus the service fee minus both rewards. Turning an option off hides its input without deleting saved values or removing them from totals. Do not auto-convert legacy fee text in notes because the note does not reveal whether the fee was already included in the original amount.
- The verified legacy-note migration is `scripts/expense-adjustment-note-migration.mjs`: dry-run is the default, `--apply` requires an exact expected count, `--verify` checks the generated backup, and `--restore` refuses to overwrite later adjustment edits. It accepts only a standalone slash-delimited `國外交易服務費／手續費 $N` segment, preserves other note segments, and keeps net spending unchanged by subtracting the already-included fee from the base-currency amount or reconciled foreign settlement before populating `serviceFee`. Its 2026-08-30 production run migrated 48 rows across two trips, enabled their service-fee option, moved NT$1,365 of fees, found no legacy rewards, and passed post-write verification. Recoverable snapshots live under ignored `.migration-backups/`; never commit them.
- The dedicated member-authorized `/trips/[tripId]/records` page centralizes each transaction's recorder and reconciliation status; keep those labels out of the normal timeline and statistics drill-down. Its batch reconciliation intentionally lists only unreconciled card expenses and reuses the authorized per-expense PATCH route. Foreign-card rows require a positive actual base-currency charge; base-currency card rows send only `reconciled: true`. Keep partial success retryable with `Promise.allSettled`, one RSC refresh after the batch, nullable API money fields handled without formatting `null`, and the records loader free of image bodies.
- Expense images and custom cover images are still stored as Base64 in database fields. Expense images are now omitted from initial client payloads, but future storage work should move the underlying blobs and custom covers to authenticated object storage/thumbnails. LINE image ingestion lives in `src/lib/line-expense-image-service.ts`, enforces a 5 MB/type limit, and uses the previous JSON value as an optimistic concurrency guard.
- Exact-money migration is intentionally staged, not applied: `prisma/manual-migrations/20260714_money_decimal_expand.sql` adds/backfills shadow Decimal columns and has a paired rollback script. Because the live schema has no Prisma migration history, never move these files under `prisma/migrations` or run them automatically; follow the adjacent README and validate on staging before dual-write code is introduced.
- This project uses the Next.js 16 `proxy.ts` convention for optimistic cookie redirects. Keep authoritative authentication and authorization in route handlers/data-access code rather than relying on the proxy.
- Keep the homepage data path server-first: `src/app/page.tsx` authenticates and calls `src/lib/trip-dashboard.ts`, while `src/app/home-client.tsx` only owns interactions. Expense/deposit POST results are merged directly into `TripDetailClient` totals and lists instead of triggering a full-trip GET; the Navbar deduplicates LINE status reads with a 60-second client cache.
- `/` is the smart launch entry: during an inclusive trip date range it redirects an `owner` or `member` to that trip; otherwise it uses the browser's `last-viewed-trip` cookie only after validating that the user is still a member. The current writable trip always wins over the remembered trip. Calendar-day resolution uses the browser-persisted IANA time zone first and Vercel's visitor time zone as fallback. `/?view=all` is the explicit escape used by manual Logo/back navigation; do not change those links back to `/` or rely on the manually maintained trip status. Overlaps resolve by latest start date, earliest end date, then stable trip ID.
- If local Next dev suddenly returns 404 for every route and `.next/dev` manifests or generated route types contain only a few/truncated entries, stop the dev server, move the generated `.next` directory aside, and restart it. Regenerating that cache restored all routes; do not diagnose the individual App Router pages until this condition is excluded.
- Cross-device trip updates use `GET /api/trips/[tripId]/version`: while the page is visible, the client checks the member-authorized transaction fingerprint every 5 seconds and fetches the full trip only when it changes, with an immediate check on focus/visibility return. Keep `src/lib/trip-version.ts` ordering-independent and include expense `createdAt`/`updatedAt`, deposit value/date/createdAt fields, cash data, and `Trip.timelineOrder`; deposits have no `updatedAt` column.
- Foreign cash is a per-trip, per-user, per-currency wallet. A `buy` exchange adds foreign cash and counts its base-currency amount as spending; cash-paid expenses only debit the wallet and are excluded from net-spending totals; a `sell` exchange debits foreign cash and reduces net spending by the base amount received. Keep wallet changes and expense/exchange writes in one Prisma transaction, including LINE edit/delete paths, and include cash wallets/exchanges in the realtime fingerprint.
- The trip timeline is a discriminated union of expenses, deposits, and cash exchanges. `Deposit.date` is the occurrence day while `createdAt` is immutable insertion order; all web transaction controls are date-only and serialize a selected calendar day as local noon. Successful new expense/deposit/exchange submissions share a browser-local, user+trip-scoped 10-minute recent-day window; edits, failures, and cancellations never renew it, and an untouched open form resets when the absolute deadline expires.
- Timeline days remain newest-first. Within a day, unmapped rows default to immutable `createdAt DESC`; `Trip.timelineOrder` stores shared cross-type manual order keys (`expense:`, `deposit:`, `exchange:`). Whole-row dnd-kit sorting is same-day only, uses 400 ms touch activation without blocking scroll, and persists through the writable-member `/timeline-order` route with authoritative child binding, browser time-zone validation, and an `updatedAt` conflict guard. New unmapped rows appear ahead of the saved order. At 600 px and below, the day header visually hides the `當日淨花費` label while retaining it for assistive technology, leaving only the no-wrap amount beside the date. An authenticated local dev render currently reports a pre-existing dnd-kit hydration warning because generated `aria-describedby` IDs differ between SSR and the client; the production build passes, but this remains known technical debt.
- Both the Trip RSC and `GET /api/trips/[tripId]` must serialize `summarizeTripSpending().exchangeNet` so the UI can state how exchanges affect the total. Exchange rows use their own editor and are editable only by their creator; amount edits apply the signed wallet delta and an all-old-values optimistic guard in one transaction. Include exchange currency, rate, date, and note in the realtime fingerprint because `CashExchange` has no `updatedAt`.
- Trip statistics are centralized in `src/lib/trip-statistics.ts`: daily fund flow is non-cash spending plus buys minus sells, while category consumption includes card and cash expenses but excludes exchanges. The separate `adjustmentSummary` reports scoped service fees, ShopBack rewards, credit-card rewards, their counts, total rewards, and net effect; keep adjustments out of consumption categories so negative rewards do not distort category percentages. Keep pre-trip/trip/all scopes aligned across all three views, preserve missing-conversion counts, fill only elapsed trip days (never future padding), and retain the category-to-expense-to-detail drill-down with scroll/focus restoration. Regression coverage is in `tests/trip-statistics.test.ts`. Trip boundary dates use their stored calendar-day prefix; transaction day grouping remains browser-local until the schema persists an explicit trip time zone or transaction calendar day.
- Reference exchange rates use CurrencyBeacon first with a 30-minute latest-quote cache, finite-positive validation, and a 6-second provider timeout; the daily open ExchangeRate-API fallback is cached for 24 hours. Seven quoted-day trends come only from same-source CurrencyBeacon timeseries data cached for 6 hours, never from mixed or fabricated history. The authenticated proxy is limited to `ALL_CURRENCIES`, 30 requests per user per minute, and a 128-entry history cache. Keep the UI explicit that these are reference estimates; actual cash exchanges remain user-entered and card totals remain reconciliation-driven. Headline rounding is presentation-only: retain the raw quote for calculations and history, and keep each displayed amount plus currency code together as a no-wrap unit across desktop and mobile widths. Keep the calculator result concise by showing the estimate without repeating the arithmetic derivation underneath.
- The reference-rate tool is intentionally absent from the transaction flow at every breakpoint. Up to 700 px, position the calculator trigger inside the trip information card's bottom-right corner, keep that card at least `10rem` high, and reserve a `4rem` right-side exclusion zone in the metadata row. The date and member count are nowrap flex items so insufficient space moves the complete member item to the next line instead of entering the trigger area. Open the full-screen Radix dialog; above 700 px, use the compact live-rate pill inside the trip title actions and the same calculator as a 430 px right drawer. The arithmetic keypad uses circular flag currency pickers and a clearly labeled left-arrow backspace control; the same-source seven-day trend stays hidden until its header icon opens a nested dialog. Keep one shared component/state so the responsive launchers never duplicate API requests. Mobile amount outputs use length-based density styles instead of ellipsis, and the currency display must remain content-height rather than restoring the former fixed `30dvh` gray gutter. Preserve scroll locking, safe-area padding, and at least 44 px controls.
- `Trip.countries` supports legacy flat country codes plus a single JSON payload containing `list` and per-day `daily`; historical trip creation could nest that payload. Reuse `parseTripCountryPlan` instead of hand-parsing it, preserve null daily slots so dates do not shift, and canonicalize newly created trips to one layer. The reference-rate card resolves its initial source currency from the current in-range travel day using the request/browser time zone, keeps manual choices while that day/currency key is stable, and resets when the day or configured destination changes.
- Trip settings dirty detection compares a canonical snapshot of every saved field, including normalized country and per-day destination arrays. Keep controls locked while saving; preserve the local draft after failed saves or unrelated member mutations; redirect to the trip with `router.replace` only after an `ok` PUT. Dirty or in-flight forms guard app links, logout, unload, and cancelable browser-history traversal; never attempt a post-commit `navigation.traverseTo()` reversal.
- The global Traditional Chinese UI font is `Huninn` loaded through `next/font/google`, with 17 px mobile and 18 px desktop root sizing. A clean production build therefore needs network access when the font is not already cached. Keep native controls inheriting the font, and use `--color-primary-text` or primary text colors for labels on dark surfaces instead of raw category/background colors.
- Manual trip edit/share/exchange/deposit overlays use `ModalScrollLock` backed by `react-remove-scroll`; keep `trip-modal-scroll-area` on inner overflow containers so the modal scrolls without moving the page and closing restores page scrolling. Category, payment, and currency selectors share the opaque `trip-choice-button` states with `aria-pressed`, group labels, and visible focus rings; do not restore transparent unselected controls.
- The expense detail/edit overlay uses the same component but widens only while editing on desktop: `.expense-editor-modal` raises the `min-width: 768px` maximum from the shared 550 px to 680 px. Keep view mode at the shared width and do not apply the wider rule below the desktop breakpoint.
- The cash-wallet expand schema in `prisma/manual-migrations/20260716_cash_wallet.sql` was applied to production on 2026-07-16 after `node scripts/cash-wallet-migration.mjs` completed a transactional dry run and verified rollback; `--apply` then passed the post-migration data checks. The paired rollback is destructive once wallet data exists. At that release, Vercel Preview had no `DATABASE_URL`, so verify preview database isolation again before relying on it for future migrations.
- The date/timeline expand schema in `prisma/manual-migrations/20260720_timeline_order.sql` was applied to production on 2026-07-20 after `node scripts/timeline-order-migration.mjs` passed its transactional dry run, compatibility-trigger exercise, schema/index checks, rollback verification, and `--apply` data verification. The insert/update compatibility triggers intentionally remain for old instances during rollout; the paired rollback is destructive once independent deposit dates or manual order data exists.
- The expense-adjustment expand schema in `prisma/manual-migrations/20260830_expense_adjustments.sql` was applied to production on 2026-08-30 after `node scripts/expense-adjustments-migration.mjs` passed its transactional dry run, rollback verification, and `--apply` schema/data checks. Existing trips default the UI toggle off and existing adjustment values to zero; the paired rollback is destructive after users save fee or reward data.
- The independent adjustment-option schema in `prisma/manual-migrations/20260830_expense_adjustment_options.sql` was applied to production on 2026-08-30 after `node scripts/expense-adjustment-options-migration.mjs` passed its transactional dry run, rollback verification, and `--apply` checks. The backfill enables only populated adjustment kinds for legacy enabled trips, or all three when a legacy enabled trip has no adjustment data. At application rollout the two populated trips had only `serviceFeeEnabled=true`, zero reward options, and zero aggregate mismatches. Its rollback drops only the three new settings; roll back the application first.
- The app is installable as a standalone PWA through `src/app/manifest.ts`, public 192/512/maskable/Apple icons, and the global `InstallAppPrompt`: Chromium uses the native install prompt, while Apple devices receive platform-specific instructions. `public/images/pwa/app-icon.svg` is the canonical artwork; when it changes, regenerate all four PNG sizes, use versioned paths in both the manifest and layout to escape installed-icon caches, and verify the white mark's visual centroid, full opacity, and maskable safe-zone fit. Keep `/manifest.webmanifest` and `/images/pwa/*` outside proxy authentication redirects. Do not add generic service-worker caching for authenticated trip/API/RSC data; introduce offline support only with an explicit user-scoped cache and invalidation design.
- Production is the Git-integrated Vercel project `travel-expense-bot`; pushes to GitHub `RafaelYang/travel-expense-bot` branch `main` deploy automatically to `https://travel-expense-bot-steel.vercel.app`. Verified post-deploy checks are `/login` = 200, unauthenticated `/` = 307 to `/login`, unauthenticated trip-version API = 401, plus a recent production error-log scan. The staged manual Decimal SQL files are documentation/runbooks only and must not be executed during ordinary app deployment.
- The user explicitly authorizes this project to be deployed after requested changes pass the relevant checks, so complete the Git-integrated production deployment and post-deploy verification instead of stopping at an uncommitted local result. Database-changing releases must still follow the migration safeguards above.
- Expense, income, and exchange timeline rows share the `transaction-list-*` layout classes and reserve a 64 px desktop/68 px mobile leading thumbnail column. The timeline shows every transaction by default while retaining the optional collapse control. Expense rows render their first signed image reference directly through unoptimized `next/image`; missing or failed images, income, and exchanges keep alignment with type-specific placeholders. At 600 px and below, keep the category as a compact badge after the thumbnail, the enlarged no-wrap amount at top right, and the item title at up to two lines. Recorder and reconciliation labels belong only on the dedicated records page; preserve the normal timeline row's full-row edit target.
